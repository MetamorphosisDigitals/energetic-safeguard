CHECKOUT INITIATION

Checkout is an intent—not access.

The customer’s payment journey and the application’s entitlement decision are deliberately separate.

01 · USER

Selects a continuity plan

The signed-in user chooses an optional plan and billing cadence.

02 · SERVER

Creates a Checkout Session

The server validates the plan and adds only user and plan metadata.

03 · STRIPE

Hosts payment collection

Payment details stay with Stripe; they never pass through the app.

04 · RETURN

Shows a confirmation state

A browser redirect can reassure the user, but it cannot grant paid capabilities.

05 · VERIFIED EVENT

Projects the entitlement

Only a signed webhook event updates the server-owned access record.

AUTHORITYAccess begins with a verified event—not a URL parameter, button click, or client-side promise.
