RELIABILITY MODEL

Reliability is built for asynchronous delivery.

Payment events can arrive late, twice, or out of sequence. The billing boundary treats each delivery as untrusted until it is verified, recorded, and safely projected.

01 · VERIFY

Check the signature

Use original request bytes, the Stripe signature, and the endpoint secret before any business logic runs.

02 · LEDGER

Record the event

A unique provider event ID makes duplicate delivery visible and prevents repeated projection.

03 · PROJECT

Protect state order

Subscription timestamps and current provider status stop stale events from replacing newer access state.

04 · RECONCILE

Compare intentionally

A controlled daily comparison flags mismatches between provider subscriptions and local entitlements.

DESIGN INTENT

Every retry is safe. Every change is auditable. Every repair is controlled.
