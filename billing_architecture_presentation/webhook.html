WEBHOOK PROJECTION PATH

Verified events project billing state.

The payment return is informational. A signed provider event is the only trigger for a durable access change.

1

Receive original bytes

The dedicated endpoint reads the untouched request body before application JSON parsing consumes it.

2

Verify signature

The server combines raw payload, Stripe-Signature, and the endpoint secret before accepting any event.

3

Ledger the event

A unique provider event ID records receipt and prevents a duplicate delivery from creating a second projection.

4

Project & acknowledge

A transaction updates customer mapping and entitlement state, marks the outcome, then returns a prompt 2xx response.

NO REDIRECT TRUST

Checkout success URLs never grant paid access by themselves.

NARROW SIDE EFFECTS

Only verified lifecycle changes can affect optional paid feature keys; rituals remain open.
